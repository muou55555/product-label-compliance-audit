## 一、问题本质

配料表审核不能只核对“已列配料是否合法”，还要反向核对“**应标而未标**”。
“水”是典型，但不是唯一——油、盐、奶、可可、添加剂等都可能漏标。
因此不做“发现水就补水规则”的打补丁，而要**泛化到任意配料**。

## 二、核心公式

```
缺失 = 应标集合 − 已标集合
```

- 已标集合：从配料表文本经同义词归一得到；
- 应标集合：由下列证据源推断，逐源累积、去重。

## 三、“应标集合”的五个证据源

| # | 证据源 | 推断方式 | 示例 |
|---|---|---|---|
| 1 | 物理形态 | 液态/半固态/浆状 → 须有液相（水或油） | 液态酱油须标水/油 |
| 2 | 生产工艺 | 盐水→水+盐；油炸→油；烘焙→水已挥发 | 油炸食品须标油 |
| 3 | 自身声明 | 正文“内含/添加 X” → X 必须进配料表 | “内含苯甲酸钠”须入配料表 |
| 4 | 品类标准 | 产品定义规定的基础原料 | 酸奶→生乳；巧克力→可可 |
| 5 | 定量闭合 | 固形物占比反推液相 | 固形物 13% → 约 87% 为水 |

证据源可叠加；任一来源推断出的配料都纳入应标集合。

## 四、豁免与边界

- **已挥发豁免**：烘焙/蒸馏/干燥中已挥发的水，不要求标示（GB 7718 §4.1.3.1.5）；
- **加工微生物**：发酵菌种（曲/酵母/乳酸菌）属加工助剂/微生物，通常不作为配料强制标示；
- **类别词不匹配**：“防腐剂/抗氧化剂”等功能类别词不当作具体配料，避免误判；
- **复合配料**：按 §4.1.3.1.3 展开原始配料（另有专用规则）。

## 五、判定与分级

- 存在应标未标 → **不符合**（nonconformity）；
- 排序/格式类问题 → 不规范（irregularity）；
- 证据不足无法判断形态/工艺 → 待人工，不臆断。

## 六、可执行实现（Skill 内自包含，不依赖外部项目）

**知识数据（`knowledge/`）：**
- `ingredient_ontology.yaml`：canonical 配料＋同义词、物理形态→必需相、工艺→必需投入；
- `required_ingredients.yaml`：品类产品标准规定的必需原料；
- `common_ingredient_completeness.yaml`：规则视角的检查项（含正反样例）。

**运行脚本：`scripts/ingredient_completeness.py`**（仅依赖 PyYAML）

```bash
# 直接参数
python3 scripts/ingredient_completeness.py --category soy_sauce \
  --ingredients "黄豆、小麦、食用盐、白砂糖" \
  --form liquid --process brine,fermentation_in_liquid --solid 13
# 传 LabelFacts JSON
python3 scripts/ingredient_completeness.py facts.json --json
```

缺失项带 canonical/来源/证据，`--json` 供下游系统调用。

## 七、扩展新品类（数据增量，无需改算法）

1. 在 `ingredient_ontology.yaml` 加该品类配料的同义词、若有新工艺则加工艺→配料；
2. 在 `required_ingredients.yaml` 加该品类标准规定的必需原料（带原句引用）；
3. 推理脚本与算法不变，自动获得完整性判定能力；
4. 规则新增须走生命周期闸门，未发布不进入实时判定。
