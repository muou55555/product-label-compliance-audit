## 一、采集与识别

### 1.0 多图清点（先做，逐张登记）
用户一次可能上传多张图（正面、背面、侧面、顶盖、局部放大）。开始前必须：
1. 清点图片总数，逐张编号 `img_1、img_2…`，标注角色（front/back/side/top/closeup）；
2. 建立**源图清单**（数量 + 路径/URL），作为证据登记与交付校验的基准；
3. 同名文件按各自 URL 分别下载并改名保存，**禁止后图覆盖前图**；
4. 每一张图都要识别、都要进证据，不允许只处理其中一张。

### 1.1 识别
1. 采集设备（高拍仪/工业相机/手机）抓拍外包装标签，尽量覆盖正面、背面、侧面、顶盖；
2. 对**每一张**原图逐字识别文字内容；对小字、模糊区做放大、分区、灰度/二值增强后再识别；
3. 同时记录：
   - **内容**：每个字段的值、引导词；
   - **格式**：像素字高、颜色、版面（front/back/side）、是否粗体/居中；
   - **图形**：条码、外箱储运标志、宣传语、签名、背书信息。

不要只做一次 OCR：识别后需回看原图核对，避免漏字、错字、把外文字母误判。

## 二、结构化事实 LabelFacts

统一成如下结构（示例字段，按实际品类增减）：

```json
{
  "category": "wine",
  "imported": true,
  "category_attributes": {"color": "red", "sweetness": "dry"},
  "has_traditional_chinese": false,
  "fields": {
    "product_name": {"value": "…", "label": "", "px_height": 23, "panel": "front"},
    "ingredients":  {"value": "…", "label": "原料与辅料", "px_height": 15, "panel": "back"}
  },
  "lab": {},
  "registry": {"registration_no": "…", "status": "…"}
}
```

- `fields`：标签上看得见的内容；
- `lab`：检测/实测值（图像无法得出，初始为空）；
- `registry`：联网核验结果（初始为空，核查后回填）。

## 三、第一步：标签形式审核（对照通用标签标准）

逐条检查（无论合规与否都记录）：

| 检查项 | 要点 |
|---|---|
| 缺项/漏标 | 名称、配料表、净含量、日期、生产者/进口商、贮存条件、许可证等是否齐全 |
| 引导词 | 如"配料/原料与辅料""贮存条件"等是否正确 |
| 字体字号 | 强制内容字高、净含量字符高度、外文/拼音不得大于汉字 |
| 单位 | 液态用 mL/L、固态用 g/kg；酒精度 %vol 等 |
| 小数点/位数 | 数值保留位数、日期年月日顺序、温度连接符 |
| 标示形式 | 净含量与名称同版面、同销售单元多包装分别标注 |
| 文字规范 | 规范汉字、不得出现繁体字（商标除外） |

## 四、第二步：内容合规审核

1. **限量查表**：按食品分类号检索添加剂/污染物/真菌毒素/营养限量表，比对检测值；
2. **品类专属指标**：按品类执行标准比对理化、感官、专属标签要求；
3. **配料/添加剂**：是否使用了不允许的物质、是否超范围或超限量；
4. **贮存条件**：标示是否与执行标准一致；
5. **声称/宣传**：不得虚假夸大、疾病预防治疗暗示、保健暗示、绝对化表述、背书风险。

## 五、逐条判定与分级

每条规则输出：`结论 + 原因 + 依据（文件/章节/原句/页码）`。

严重度：**不符合 ＞ 风险提示 ＞ 不规范 ＞ 待人工/待检测/待核验/待联网 ＞ 符合**。

- 形式错误但内容可用 → 多为"不规范"；
- 明确违反强制要求/限量 → "不符合"；
- 需检测/实物/联网/人工才能定 → 对应"待检测/待核验/待联网/待人工"。

## 六、边界与失败分支

- 图像**无法**得出：残留量、理化、微生物、净含量短缺量、物理字高 → 必须送检/实测，判"待检测/待核验"；
- 联网核查失败/接口加密 → 换真实浏览器或官方渠道，仍失败判"待联网/待人工"；
- 未覆盖品类 → 通用规则+查表先行，专属项"待人工"，不假装合规；
- 模型异常 → 降级"待人工"，记录失败类型，不阻断全流程。
